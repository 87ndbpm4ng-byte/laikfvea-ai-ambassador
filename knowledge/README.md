# Knowledge Framework

## Purpose

This folder is the future source library for approved company, science, product, support, and conversation-guidance documents. It is intentionally not connected to retrieval, OpenAI, or the current visitor interface.

The files currently contain templates only. They are not product documentation and must not be treated as factual sources.

## Source-of-truth policy

- All factual information must come from an approved, traceable source.
- Official user manuals will become the primary source of truth for product operation, features, limitations, and support information.
- Approved company documents may provide company and exhibition guidance.
- Approved brochures and product specifications may supplement manuals when their claims are current and consistent.
- Scientific references require explicit review before any statement is presented to visitors.
- Unsupported, inferred, outdated, or untraceable claims must never be added.

If approved sources disagree, contributors must stop and request a content-owner decision. They must not combine or reinterpret conflicting statements.

## Folder organisation

```text
knowledge/
├── company/   Approved company and exhibition material
├── science/   Approved scientific explanations and references
├── products/  Product manuals, product facts, and comparisons
├── support/   Approved FAQs, terminology, and troubleshooting
└── prompts/   Content-governance and conversation-style guidance
```

New documents should be placed in the narrowest relevant folder. Add files instead of changing the folder structure when importing future manuals, PDFs, brochures, specifications, references, or internal documents.

## Contributor workflow

1. Identify the authoritative source and its owner.
2. Record the source title, version, publication date, and approval status in the relevant document.
3. Add only statements supported directly by that source.
4. Preserve exact units, qualifiers, limitations, warnings, and conditions.
5. Mark unresolved gaps clearly instead of inferring an answer.
6. Request specialist review for scientific, health, safety, legal, or regulatory language.
7. Review comparisons against the current approved documents for every included product.
8. Keep source changes separate from interface changes so factual revisions remain auditable.

## Future import recommendations

- Keep original source files in approved document storage rather than committing unreviewed binaries here.
- Convert approved source material into focused Markdown documents with traceable references.
- Split large manuals by stable subject only when the original source location remains recorded.
- Preserve document version and locale metadata so future retrieval can filter by product, language, and revision.
- Use stable, descriptive filenames and avoid duplicating the same fact across multiple documents.
- Add translated documents as reviewed locale-specific sources later; do not machine-translate regulated or scientific claims without approval.
- Treat future voice output as another presentation channel over the same approved knowledge, not as a separate factual source.

## Current status

All documents in this folder are placeholders. Real information will be added later from official user manuals and other approved company sources.
